# Three-pass project review — 2026-09-05–06

## Scope and method

This review covers the authored project: all eleven published guides, the
three parked research guides, the talk, five research notes, project
instructions, website generator, stylesheet, tests, and build workflows.
The reviewers read the complete authored sources, then checked consistency
and challenged the arguments in separate passes. This is not a formal
verification or a guarantee that every statement is error-free.

The passes have different purposes:

1. **Correctness:** full source reading, tracing relevant protocol and
   implementation claims to their pinned sources, and a baseline PDF build.
2. **Coherence:** reconcile assumptions, notation, boundaries, numerical
   examples, historical findings, and generated output across documents.
3. **Adversarial verification:** revisit the revised reasoning and disputed
   findings, run independent arithmetic checks, rebuild the retained
   documents, and inspect website links and representative rendering.

Detailed source coverage and evidence are recorded in the companion reports:

- [Foundations](audit-foundations-2026-09-05.md): Math, Crypto, Halo 2.
- [Deployed protocol](audit-deployed-2026-09-05.md): Consensus, Ironwood,
  Wallet, Sync.
- [Frontier and research](audit-frontier-2026-09-05.md): FlyClient, ZSA,
  Crosslink, FROST, and the three parked subjects.

Local upstream trees under `/home/m/zcash` were read, not modified. Historical
pins remain historical pins: neither a release's absence from a local clone
nor a draft's presence there establishes current release or deployment status.

## Cross-project corrections

- Distinguished a note's membership from its unspentness, proof witnesses
  from spending authority, and circuit equations from the signatures,
  integer ranges, and state checks needed for complete validation.
- Corrected the talk's Action predicates, Sinsemilla commitment addition
  and domain separation, nullifier assumptions, disclosure boundaries,
  note-decryption checks, and the interpretation of the four-row example.
- Scoped the setup discussion as an illustration rather than an exact

  a compromised ceremony and a proving-system replacement from fund migration.

  that a draft or a crate's presence establishes an integrated secure system.
- Marked the old correctness and defect dossiers as dated records, not
  verified current patch queues. Corrected the release/tag conflation,
  deepest-first header order, snapshot-height arithmetic, and padding
  round-trip claim in the old reports.
- Corrected lightwalletd comparison claims: it rejects unsupported block
  hash requests instead of resolving them; the TreeState byte-order example

  split to the parser/circuit discrepancy actually evidenced. Full-node
  acceptance was not reproduced; `0x04` also fails the independent rule that
  at least one of spends or outputs must be enabled.

The individual reports describe the substantive mathematical and protocol
corrections within each volume. Existing labels were preserved to avoid
breaking references; conventions now explicitly acknowledge legacy label
namespaces. Existing user edits, including the talk's new worked example,
were retained.

## Build and regression checks

The small existing generator remains in place. Following the ponytail skill,
changes are local fixes and standard-library checks, not a new documentation
framework:

- Website postprocessing is idempotent and retries a complete-edition build
  when its directory exists but its index does not.
- The website workflow supplies the stylesheet at conversion time, not only
  after conversion. Postprocessing normalises LaTeXML's copied stylesheet
  URL to the shared site asset; the final link check caught the bad URL.
- `site/tools/check_build.py` compiles all fourteen guides, the talk, and
  the complete edition. It rejects compilation errors, overfull boxes,
  unresolved or duplicate references, duplicate PDF destinations, and
  missing glyphs. `--update-pdfs` copies PDFs only after every document passes.
  It also rejects duplicate document environments and content that TeX would
  silently discard after `\end{document}`. The latter guard was added after
  catching and correcting an intermediate edit's duplicated suffix.
- `site/tools/check_site.py` checks local `href`/`src` links, fragment targets,
  duplicate HTML IDs, empty image sources, and LaTeXML error markup; the
  website workflow runs it after search indexing. Regression cases exercise
  each of these failures.
  It is not a CSS `url()`, `srcset`, or JavaScript resource crawler;
  representative browser checks cover integration separately.

The retained numerical checks are also part of the PDF workflow:

```sh
python3 -B research/check_foundations.py
python3 -B research/check_deployed.py
python3 -B research/check_frontier.py
python3 -B site/tools/test_sitegen.py
python3 -B site/tools/check_build.py --update-pdfs
python3 -B site/tools/check_site.py <generated-site-directory>
```

The foundation check covers both F97 traces, 1,872 exact extractor cases,
and 121 formal-generator IPA identities. The deployed check includes the
90 probability cells, 33 strict confirmation thresholds and 30 profit-table
floors actually printed in the source, plus independent identities and
F4Jumble vectors. The frontier check has nine numerical/model tests.

Local HTML conversion used LaTeXML 0.8.8 installed under the ignored build
directory. Attempts with both installed Magick backends failed after writing
the Wallet pages. Disabling their optional image-processing hook used
LaTeXML's existing Image::Size/native PNG path for the already-rendered
figures. The final Math, Crypto, and complete-edition conversions additionally
used `--noparse`; the site renders their retained TeX `alttext` with MathJax,
not LaTeXML's semantic maths parser. This is a local validation configuration,
not a change to the production workflow or a claim that a failed command
passed. A separate normal-parser Crypto test also completed with a local
status-preserving Perl shutdown shim. That diagnostic does not establish the
cause of every converter failure. The ordinary CI toolchain was not run
remotely.

The final `--update-pdfs` run passed all **16 documents**, including the
latest proof corrections, and refreshed their tracked PDFs. There were no
overfull boxes, unresolved/duplicate references, missing glyphs, or duplicate
PDF destinations. The three numerical checks, site-tooling regressions, and
`git diff --check` also passed. Representative PDF inspection covered the
revised setup/Sinsemilla slides, Wallet's split theorem, and Consensus's
formerly orphaned theorem bar; no clipping remained in these examples.

The generated site's link/ID gate passed **198 HTML pages**, including all
eleven standalone volumes and the complete edition. Search indexed **97
standalone pages**; the complete edition is deliberately excluded to avoid
duplicate results. All final pages were written before checking, and the
latest Crypto proof wording was verified in both editions.

The final Math and complete-edition converter processes were terminated
after all page writers and postprocessing finished, while they continued
consuming CPU without further output. They therefore **did not pass an
end-to-end process-exit check**. The HTML artifact checks above passed
independently; this local converter shutdown problem remains a toolchain
limitation, not a silently waived successful command.

Chromium smoke checks passed at **1440 px and 390 px** on the landing page
and representative Math, Crypto, Halo 2, Consensus, Wallet, and complete-edition
pages: fourteen page/viewport cases. They found no horizontal overflow,
MathJax error nodes, broken images, JavaScript page errors, or HTTP error
responses other than the intentionally ignored favicon request. Theme
switching worked, and a search for `nullifier` returned results. Math's group
chapter alone rendered 895 maths elements at each width. Screenshots of the
final desktop and mobile output were inspected; this was representative
browser coverage, not a visual inspection of every page at every viewport.

Local validation artifacts and detailed logs are retained under the ignored
`build/audit-2026-09-05/` directory; the generated website is in `site-final/`.
PDF gate outputs and logs are in `build/pdf/`. No commit, push, or deployment
was performed.

## Evidence and limits

The protocol specification and applicable ZIPs are authoritative; these
guides are explanatory. Useful primary sources checked for the cross-project
corrections include the [protocol specification](https://zips.z.cash/protocol/protocol.pdf),
the [Orchard nullifier design](https://zcash.github.io/orchard/design/nullifiers.html),
[ZIP 258](https://zips.z.cash/zip-0258), and the
[Orchard release history](https://github.com/zcash/orchard/blob/main/CHANGELOG.md).
The companion reports identify implementation pins and files.

Vendored MathJax and fonts were treated as third-party assets: availability
and representative integration were checked, not every vendored statement
or binary. Ignored scratch files and old generated build directories are
not maintained project sources. No upstream issue was filed, no upstream
implementation changed, and no live-network exploit or consensus failure
was attempted. Historical defect entries still need reproduction and owner
review before being presented as current vulnerabilities.

Passing numerical examples and builds does not prove cryptographic security,
paper theorems, the absence of undiscovered errors, or future source currency.
